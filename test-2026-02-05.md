## Issues Identified and Analysis

### Issue 1: RuntimeType Enum Handling (HIGH PRIORITY)

**Error:** `AttributeError: 'str' object has no attribute 'value'`

**Location:** `altstore/core/types/manifest_schema.py:171`

**Problem:** In `AppManifest.to_dict()`, the code assumes `self.run.type` is a `RuntimeType` enum, but tests pass it as a string.

```python
# Current code:
'type': self.run.type.value,  # Fails when type is a string

# Should handle both:
'type': self.run.type.value if isinstance(self.run.type, Enum) else self.run.type
```

**Files Affected:**
- `altstore/core/types/manifest_schema.py` (lines 171, 187)

**Fix Complexity:** Low (1-2 hours)

### Issue 2: Missing Import in dry_run.py (MEDIUM PRIORITY)

**Error:** `NameError: name 'NetworkPolicy' is not defined`

**Location:** `altstore/sandbox/dry_run.py:211`

**Problem:** The `MalwareDetector.scan_app()` method references `NetworkPolicy` but it's not imported in the module.

**Fix:** Add import:
```python
from ..core.types.manifest_schema import NetworkPolicy
```

**Fix Complexity:** Low (15 minutes)

### Issue 3: Undefined Variable in github_explorer.py (MEDIUM PRIORITY)

**Error:** `NameError: name 'has_docker_indicators' is not defined`

**Location:** `altstore/client/github_explorer.py:310`

**Problem:** Variable used before definition in `_classify_repo` method.

**Fix Complexity:** Low (30 minutes)

### Issue 4: Import Path Error in formal_verifier.py (MEDIUM PRIORITY)

**Error:** `ModuleNotFoundError: No module named 'altstore.core.core'`

**Location:** `altstore/core/validation/formal_verifier.py:6`

**Problem:** Incorrect relative import path:
```python
# Current (wrong):
from ..core.types.manifest_schema import ...

# Should be:
from ..types.manifest_schema import ...
```

**Fix Complexity:** Low (15 minutes)

### Issue 5: Dictionary vs Object Access (MEDIUM PRIORITY)

**Error:** `AttributeError: 'dict' object has no attribute 'publisher'`

**Location:** `altstore/core/security/trust_model.py:141`

**Problem:** The `SecurityManager.assess_application()` method expects a manifest object but receives a dictionary in tests.

**Fix:** Update tests to pass proper objects OR add dictionary support in the security manager.

**Fix Complexity:** Medium (2-3 hours)

## Architecture Assessment

### Strengths

1. **Comprehensive Manifest System** - Well-designed YAML/JSON manifest schema with validation
2. **Security-First Design** - Multi-layered sandboxing, trust scoring, malware detection
3. **Offline-First Architecture** - Capsule system for air-gapped installations
4. **Federated Index** - Decentralized app distribution without single point of failure
5. **WASM Fallback** - Secure execution for untrusted applications
6. **Reproducible Builds** - Deterministic build verification for trust

### Areas for Improvement

1. **Type Consistency** - Mixed use of enums vs strings, objects vs dicts
2. **Import Organization** - Now fixed, but revealed fragility
3. **Error Handling** - Some modules lack proper error boundaries
4. **Test Coverage** - Integration tests exist but need more unit tests
5. **Documentation** - Some modules lack docstrings

## Structural Improvements

### 1. Plugin Architecture
Convert build strategies and sandboxes to plugins:
```python
class BuildStrategy(Plugin):
    name: str
    def build(self, manifest: AppManifest) -> BuildResult: ...

class Sandbox(Plugin):
    name: str
    def execute(self, artifact: Path, config: SandboxConfig) -> ExecutionResult: ...
```

### 2. Event-Driven Architecture
Use events for decoupled components:
```python
@event_handler(AppSubmittedEvent)
def on_app_submitted(event: AppSubmittedEvent):
    # Trigger malware scan, reproducible build, etc.
```

### 3. GraphQL API
Add GraphQL for flexible client queries:
```graphql
query {
  apps(filter: {trustLevel: VERIFIED}) {
    id
    name
    publisher { name verified }
  }
}
```
